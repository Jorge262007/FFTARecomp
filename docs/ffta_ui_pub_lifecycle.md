# EUR Pub root window lifecycle

Verified on stage 62 on 2026-10-21 from read-only process memory; no screenshots of transitions.

## Cause

The original window object is allocated, draws its entry animation, and only then initializes its cursor callback (EUR 08018fc5). The old presentation reader depended on that callback and on interactive list flags. It therefore discovered a different visual owner after the opening animation. Its cursor-derived rectangle also started at Y76, while the real window starts at Y72. Closing changes cursor flags from 0F to 0D, independently of the window animation.

## Original window object

Offsets are relative to its pair of map pointers, not a fixed EWRAM allocation:

| Offset | Meaning | Observed root |
| --- | --- | --- |
| +00,+04 | Text and backing VRAM maps | 06005800,06005000 |
| +10 | Canonical X,Y,width,height in tiles | 0,9,11,11 |
| +14,+16 | Frame style and backing resource | 0180,0C20 |
| +18 | Window type | 00010005 |
| +20,+22 | Current animated width,height | Width 0,2,4,6,8,10,11 |
| +24,+26 | Target width,height | 11,11 on entry; 0,11 on exit |

Offsets use hexadecimal notation. The canonical rectangle is independent of current animated extents. Presentation includes one extra tile to the right for the compact cursor, giving bounds [0,72,96,160].

## Fix

ffta_ui_window reads this object without requiring a cursor. The same source rectangle, left/bottom anchor and uniform user scale remain active through entering, open and exiting. The original window renderer continues to animate its current extent. A hidden/reused window never retains old pixels. The cache stores only the validated owner address, and its signature is checked every frame. Mouse conversion uses containment in the actual visual owner rather than assuming that its origin is always sixteen pixels above the first list row.

Scope is deliberately EUR Pub root only. Other windows require their producer/style to be measured before extending this profile.

## Reproducible check

The optional pub_window_replay example consumes recordings in target/pub-lifecycle (not distributed). It replays the measured window metadata and tile maps through the PPU, checking the semantic node geometry and anchor and ensuring EWRAM remains unchanged. The two recorded sequences cover 302 visible root samples: 10 entering, 282 open, 10 exiting; 12 samples are before cursor creation. All preserve the same bounds and anchor. These are sampled states from two runs, not an assertion of 302 distinct guest frames. Final visual acceptance belongs to the user.
